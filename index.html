Project Overview

One transmitter. Any receiver.

AIO-TX isn't built for one single purpose — it's a universal wireless control interface designed to fit almost any project that needs real-time, two-way communication.

📡

Multi-Protocol

WiFi 6, Bluetooth Low Energy, and ESP-NOW on one board — with CAN Bus planned for REV 3.0.

🔐

Two Pairing Modes

A fast, unauthenticated ESP-NOW mode for trusted setups, and a PIN-authenticated Smart Connect mode for secure sessions.

🖥️

Standalone UI

Full onboard OLED interface — configure modes, enter WiFi credentials, and read live telemetry with no phone or laptop needed.

🎮

Full Control Surface

17 tactile inputs: dual D-pads, dual analog channels, and system controls, all read through a single I2C-based MCP23017 expander.

📶

Live Telemetry

Round-trip ping and packet-loss percentage shown in real time, plus whatever telemetry your receiver reports back.

🖱️

BLE HID Mode

The same hardware can act as a wireless mouse, keyboard, or media remote for any phone, tablet, or PC.

Companion Library

Smart Connect

An open-source Arduino library that handles the entire wireless pairing handshake for you — so building a receiver means writing your own control logic (drive a motor, flip a relay), not a radio protocol from scratch.

Runs on ESP32 and ESP8266

On ESP32 it runs on its own FreeRTOS task pinned to core 0. On ESP8266 (no FreeRTOS in the Arduino core) it runs cooperatively — just call tick() once per loop().

Display is optional where it can be

In plain ESP_NOW mode, no display is required — the library runs fully headless. In Smart Connect mode, a display is required (there's no other way to show the pairing PIN), and setup blocks with a clear message until one is detected.

Quick Start

Minimal receiver — advertises, pairs, and prints incoming D-pad/analog state:

Basic_Receiver.ino
#include <Smart_Connect.h>

Smart_Connect receiver;

void setup() {
  Serial.begin(115200);

  // name, OLED SDA pin, OLED SCL pin, smartConnect (false = plain ESP_NOW), task priority
  receiver.setup("AIO-RX-Bot", 21, 22, false, 1);
  receiver.run();
}

void loop() {
  receiver.tick();  // required every loop() — no-op on ESP32, drives the state machine on ESP8266

  if (receiver.isConnected()) {
    String state = receiver.readAll();
    Serial.println(state);  // "U;D;L;R;C:U;D;L;R;C:analog1:analog2"
  }
}

API Reference

MethodReturnsDescription
setup(name, sda, scl, smartConnect, priority)voidInitializes I2C/OLED, WiFi, and ESP-NOW. Call once in setup().
run()voidStarts the receiver state machine (a FreeRTOS task on ESP32; arms cooperative mode on ESP8266).
tick()voidDrives the state machine on ESP8266. Call every loop(). Safe no-op on ESP32.
readAll()StringThread-safe snapshot of the last received command: "U;D;L;R;C:U;D;L;R;C:a1:a2" — DPAD1, DPAD2, then two 0-100 analog values.
isConnected()boolTrue while a transmitter is actively paired.
getState()ReceiverStateThe raw state machine value: RX_IDLE, RX_ADVERTISING, RX_HANDSHAKE, RX_PIN_WAIT, RX_CONNECTED, or RX_DISCONNECTED.
setTelemetry(const char* data)voidSets the string sent back to the transmitter on every received command (e.g. battery level, sensor data, status).

Wiring a Receiver — Example

Driving an L298N motor driver from a NodeMCU (ESP8266), controlled by the transmitter's left D-pad:

L298N_Receiver.ino
#include <Smart_Connect.h>
Smart_Connect receiver;

constexpr uint8_t IN1 = D1, IN2 = D2;  // Motor A
constexpr uint8_t IN3 = D7, IN4 = D8;  // Motor B — kept off D3/D4 (boot-strap pins)

void setup() {
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);

  receiver.setup("AIO-RX-Bot", D5, D6, false, 1);  // OLED on D5/D6
  receiver.run();
}

void loop() {
  receiver.tick();

  if (receiver.isConnected()) {
    String cmd = receiver.readAll();
    // parse cmd, drive IN1-IN4 accordingly, then:
    receiver.setTelemetry("MOTOR:OK");
  }
}

Note: on ESP8266 boards, avoid wiring motor/actuator control pins to D3/D4 (GPIO0/GPIO2) — these are boot-strapping pins and must read HIGH at power-on, or the board can fail to boot correctly.

Under the Hood

How pairing actually works

Both pairing modes ride on the same ESP-NOW radio and are fully handled by the library — this section is for anyone extending or debugging it.

Advertising

The receiver broadcasts an advertise packet twice per second, including its name and MAC address. It does not scan — the transmitter finds it.

Handshake (ESP_NOW mode)

The transmitter sends a Hello packet. The receiver replies with Hello_ACK, then CONN_OK. The transmitter echoes CONN_OK back — session open. No PIN, no encryption.

PIN Authentication (Smart Connect mode)

After a connection request, the receiver generates a random 4-digit PIN via hardware RNG and displays it on its OLED. The transmitter must submit a matching PIN before the session opens.

Active Session

The transmitter streams D-pad and analog state continuously; the receiver replies with whatever telemetry string you set via setTelemetry(). Every handshake packet is retransmitted every ~500ms so a single dropped packet never stalls pairing.

Watchdog Teardown

If either side goes silent, the connection is automatically torn down — the receiver won't keep driving motors on a stale last command if the transmitter disappears.
